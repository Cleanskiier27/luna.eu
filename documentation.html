Documentation

Project operation, validation, publishing, and delivery reference.

PHASE 1Install and run locally

Clone the repository, open its static application directory, and serve it over HTTP. A local server is recommended because browser APIs require a secure or localhost origin.

git clone https://github.com/Cleanskiier27/luna.eu.git
cd luna.eu/GITREPOVSLOCAL
python -m http.server 8000
# Open http://127.0.0.1:8000/

PHASE 2Use the application

  1. Launch the NetworkBuster application.
  2. Select an operating system and target device.
  3. Review optional configuration settings.
  4. Use agent mode only for supported local workflows.
  5. Open HTML tools to scan and organize local HTML files.

PHASE 3Refresh the local HTML catalog

powershell -ExecutionPolicy Bypass -File .\html-fetch-tool\fetch-html.ps1 -NoOpen
# Optional custom directory:
powershell -ExecutionPolicy Bypass -File .\html-fetch-tool\fetch-html.ps1 -ScanRoot C:\path\to\scan -NoOpen

The generated browser catalog is local data. Review file paths before publishing or sharing.

PHASE 4Test and validate

  • Confirm the landing page, application, history, and HTML tool all return HTTP 200.
  • Validate HTML files with a standards parser.
  • Scan committed content for access tokens and GitHub credentials.
  • Review GitHub Actions before merging deployment changes.

PHASE 5Publish

Push to main. GitHub Actions runs the test phase, packages GITREPOVSLOCAL, and deploys it to GitHub Pages.

Production: https://cleanskiier27.github.io/luna.eu/

PHASE 6Package delivery

Download the source archive from GitHub or create a local ZIP after committing. Exclude generated local scan output and the Git metadata directory.
